<objective>
Fix the one verified, real, currently-shipping bug in `InMemoryStore`: `get_active_entries()` and
the private `_count_active()` never filter by `hold.expires_at`, so an expired-but-never-released
hold occupies capacity forever. Collapse both into the ONE shared, expiry-filtering
`get_active_entries()` primitive (AVAIL-03's literal wording), have `place_hold` reuse it, and delete
the duplicate scan.

Purpose: this is the phase's other verified-real bug (alongside 02-01's midnight-crossing fix) —
RESEARCH.md confirmed by direct source read that Phase 1's own tests never exercised a hold past its
TTL, so the gap shipped uncaught. AVAIL-03's requirement text names the fix directly: one shared
primitive, not a duplicated check.

Output: `InMemoryStore.get_active_entries()` excludes expired holds; `_count_active()` is deleted;
`place_hold` calls the shared primitive; a time-machine-based end-to-end test proves an expired hold
stops blocking capacity with no explicit release.
</objective>

  rather than deleting the expired record, and avoids adding a new deletion side-effect to what is
  otherwise a pure read-path fix.
