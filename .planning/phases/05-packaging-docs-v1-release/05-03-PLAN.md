    the ONE file in this repo allowed to import `chatbot_engine` (CLAUDE.md's one-way dependency rule

    - `__init__(self, engine: SyncAvailabilityEngine)`; store it plus two instance attributes: a
      `dict[str, str]` mapping each `place_hold` call's `idempotency_key` to the `hold_id` it produced
      (`self._hold_keys`), and a `set[str]` of idempotency keys whose hold has since been confirmed
      (`self._confirmed_keys`).
    - `query_availability(resource_type, window, party_size)`: treat `resource_type` as the engine's
      `resource_id` verbatim (single-mapping v1, no separate type→id lookup layer). Call
      `self._engine.get_availability(resource_type, window[0], window[1])`. For each `PublicSlot` in

      `Slot(slot_id=..., resource_id=s.resource_id, starts_at=s.start, ends_at=s.end,
      capacity=s.remaining)`.
    - `place_hold(slot_id, ttl_seconds, idempotency_key)`: parse `resource_id, start_iso, end_iso =
      slot_id.split("|")`, parse both timestamps back to `datetime`. Call
      `self._engine.place_hold(resource_id, start, end, ttl_seconds,
      idempotency_key=idempotency_key)`. Catch `(CapacityExhaustedError, OutsideHoursError,
      ResourceNotFoundError)`: if `idempotency_key in self._confirmed_keys`, raise `HoldConflict` (a
      retry whose original hold was already confirmed into a booking must fail loudly per
      `AvailabilityPort.place_hold`'s docstring, never a misleading `SlotUnavailable`); otherwise
      raise `SlotUnavailable`. Catch `IdempotencyConflictError` directly: raise `HoldConflict` (the
      reused-key-for-a-different-slot case). On success, record `self._hold_keys[idempotency_key] =
      hold.id` (only when `idempotency_key` is truthy) and return `Hold(hold_id=hold.id,
      slot_id=slot_id, expires_at=hold.expires_at)`.
    - `confirm_hold(hold_id, details)`: call `self._engine.confirm_hold(hold_id, dict(details),
      idempotency_key=hold_id)` — passing `hold_id` itself as the engine's own idempotency key is
      what gives "repeated confirm_hold(same hold_id) returns the SAME booking" for free, via the
      engine's existing fingerprint-based idempotency (same `hold_id` + same `details` → same
      fingerprint → cached replay). Catch `(HoldExpiredError, HoldNotFoundError)`: raise
      `HoldExpired`. On success, look up which `place_hold` idempotency_key (if any) produced this
      `hold_id` by scanning `self._hold_keys` for a value equal to `hold_id`, and add that key to
      `self._confirmed_keys` (this is what `place_hold`'s catch block above checks to distinguish "a
      genuinely capacity-exhausted retry" from "a retry whose original hold was already confirmed").
      Return `Booking(booking_id=booking.id, slot_id=f"{booking.resource_id}|
      {booking.slot_start.isoformat()}|{booking.slot_end.isoformat()}",
      confirmation_ref=booking.id)` — reusing the engine's own already-`uuid4()` `booking.id` (which,
      per `storage/memory.py`, equals the original `hold.id`) as BOTH `booking_id` and
      `confirmation_ref`, rather than minting a fresh uuid — this is what makes all three bearer
      tokens (hold_id/booking_id/confirmation_ref) the same underlying value for a given reservation,
      which is what makes `cancel(ref)` below work uniformly.
    - `cancel(ref)`: try `self._engine.cancel_booking(ref)` first; on success return. On
      `BookingNotFoundError`, fall back to `self._engine.release_hold(ref)` (idempotent no-op on any
      unknown or non-hold id) and return `None` either way — never raise from this method.
